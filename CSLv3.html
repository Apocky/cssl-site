§1 · What CSLv3 is

CSLv3 (Caveman Spec Language v3) is a specification notation. It encodes specs, structured reasoning, and — in its executable subset — programs, using a 74-glyph inventory with mandatory ASCII aliases, a positional slot grammar, and Sanskrit-derived compound operators. The grammar is LL(2): a parser needs two tokens of lookahead, no backtracking.

The central move is to strip natural-language ceremony — articles, auxiliaries, hedging, passive voice — and recompose what remains through operators that carry the grammatical relationship. A 10,000-word English system spec compresses to roughly 2,000–2,500 tokens while preserving every implementation-relevant detail. In a 128K context window, that converts to ≈640K–768K tokens of effective spec capacity.

CSLv3 is used in three settings: (1) human↔AI spec writing, where the same document drives both human comprehension and LLM reasoning; (2) chain-of-thought substrate, where <think> blocks follow a fixed §P / §D / §T / §S / §C skeleton; (3) input to a reference compiler whose executable subset treats the spec as the code. The parser, typecheck, IR, SMT discharge, LSP, and multi-target codegen all ship in v1.0.

Not to be confused with CSSL. The site root (cssl.dev) documents Sigil, which is the shorthand for CSSL (Caveman Sigil Substrate Language) — a systems programming language compiling to x86-64 + SPIR-V. Sigil is a compiler; CSLv3 is a notation. They share the density thesis but are separate projects.

§3 · Five compound types

Relationships between terms are encoded by the operator joining them, not by English prepositions. The five compound types come from Sanskrit samāsa (Pāṇini, ~4th c. BCE) and compose recursively.

.

Tatpurusha

“Y of X” — determinative. Rightmost element is head; left modifies. Most common compound; the default.

render.pipeline
+

Dvandva

“X and Y” — copulative. Flat union of co-equal items; all have equal standing.

cpu+gpu
-

Karmadhāraya

“Y that is X” — appositive. Distinct from tatpurusha: relational vs attributive.

static-mesh
⊗

Bahuvrihi

“having X and Y” — exocentric. Refers to something outside itself, characterized by the compound.

fire⊗resist
@

Avyayibhava

“at / per / in scope of X” — adverbial / locative. Scopes an operation or value to a context.

@frame

Compounds nest: sys.render.pass.shadow.shader.frag = frag of shader of shadow of pass of render of sys. Explicit parentheses are required where nesting creates ambiguity.

§4 · Glyph inventory

74 canonical glyphs, organized in three tiers by learning priority. Every Unicode glyph has a mandatory ASCII alias — BPE tokenizers on modern LLMs can split a single Unicode symbol into 3–5 tokens, which would destroy the compression advantage. When a glyph costs 3+ BPE tokens, the ASCII form is preferred. The BPE column is measured under Claude/GPT-4 tokenizers.

§5 · Slot grammar

Every statement follows a fixed positional template (Ithkuil-derived). Defaults are silent: only non-default slots are written. This is the single largest source of compression on routine lines.

[EVIDENCE?] [MODAL?] [DET?] SUBJECT [RELATION] OBJECT [GATE?] [SCOPE?] [META?]
Slot defaults — omit when matching, write only deviations
SlotDefault (silent)Example non-default
EVIDENCE✓ confirmed△ hypothetical · ◐ partial
MODALassertionW!, R!, M?, N!
DETnone§ system · ∫ field · ⊞ spatial
RELATION: (is / has)::, =, →, ∈, ⊂
GATEunconditionalif expr, when expr, unless expr
SCOPEglobal@frame, @chunk, @init

Worked expansion

Minimum statement:

player.hp u16

Fully slot-expanded:

✓                    # evidence: confirmed (default)
:                    # modal: assertion (default)
player.hp           # subject: hp of player
:                    # relation: is (default)
u16                  # object: unsigned 16-bit integer
# gate: unconditional (default)
# scope: global (default)

Fully-slotted — every default overridden:

△ W! §render.pipeline :: forward-pass ⌈latency < 16ms⌉ @frame

Reads: hypothetically, the render pipeline must be a forward pass, with the constraint that latency stays under 16ms, scoped per frame.

§6 · Morpheme stacking

Aspect, modality, certainty, and scope suffixes attach to any term via dot notation. Fixed composition order: aspect · modality · certainty · scope.

§7 · Reasoning substrate

Inside <think> blocks, reasoning follows a five-stage skeleton: §P problem, §D decomposition, §T trace, §S synthesis, §C check. The structure resists drift back to verbose English — a known failure mode in LLM chain-of-thought.

Five reasoning stages
StagePurposeGlyphs
§P · ProblemState facts + goal (2–3 lines).given: goal:
§D · DecompositionBreak goal into subproblems.G → [sub₁, sub₂, ...]
§T · TraceTry each; mark results.~> try · ✓ ok · ✗ fail · ∵ because
§S · SynthesisCombine partials.⊕ combine · ⇒ derive
§C · CheckVerify + flag edges.✓ pass · ⚠ edge-case

Example

<think>
§ P
  voxel engine stutter @ chunk boundary
  hw: Intel 12-14gen + Arc A770

§ D
  stutter → [mesh.regen, alloc.spike, gpu.stall]

§ T
  mesh.regen  ~> profile     → 2ms   ✓ ¬culprit
  alloc.spike ~> heap-trace  → 47MB burst  ?!
    ⤓ source = chunk-LOD-promote  ✓ found
  gpu.stall   ~> pipeline-stats → idle 0    ✓ clean

§ S
  culprit = alloc.spike ∵ LOD-promote allocates fresh
  fix → pool.LOD-buffers + ring.allocator

§ C
  ✓ eliminates 47MB spike
  ⚠ edge: extreme LOD jumps → pool-overflow? → cap+fallback
∎
</think>

Same chain in English: ~45 tokens. In CSLv3: ~18. ≈2.5× compression on reasoning — less than the 5-6× on specs because chain-of-thought has less structural regularity, but still substantial.

Layered from practical primitives to dependent types. Lower tiers for daily use; higher tiers surface only where the problem demands them.

Caveat — LLM familiarity ≠ density. APL is dramatically denser than CSLv3 on raw character count, but LLMs score it with higher per-token perplexity because they've seen far less of it in training. The same bias inflates Lojban perplexity. CSLv3 sits deliberately in the middle: dense enough to compress 5–6× over prose on spec content, but built from primitives (ASCII aliases, dot-compounds, suffix morphemes) that modern tokenizers handle well. These numbers measure different things in different coordinate frames — do not read them as a ranking.

§10 · Spec template

Every CSLv3 spec has the same canonical shape. Six headers are the minimum an implementer needs to act.

§ <NAME>.spec

§ GOAL
  what: ⟨one-line⟩
  why:  ⟨one-line⟩

§ DATA
  def X't ⟨
    field : T  # comment if needed
    ...
  ⟩

§ OPS
  fn op₁ (x :: X) → Y
    pre:  ⌊cond⌋
    post: ⌈cond⌉
    body: ⟨CSL or target-lang code⟩

§ INVARIANTS
  t∞: ∀x ∈ X: P(x)

§ TESTS
  case₁: input → expected  ✓
  case₂: input → expected  ✓
  edge:  boundary → behavior ✓

§ ANTI-PATTERNS
  ✗ don't: ⟨pattern⟩ ∵ ⟨reason⟩
  ✓ do:    ⟨alternative⟩
∎

Density rules: drop articles, auxiliaries, passive voice, restatement-of-header. Replace "because" → ∵, "therefore" → ∴, "for all" → ∀, "must" → W!, "should" → R!, "may" → M?. Keep numbers, formulas, code, types, relationships.

§11 · Worked example — HTTP request handler

Domain-neutral, written to the template above. From specs/06_SPEC.csl.

§ http.handler.spec                    ◐

§ GOAL
  what: route HTTP request → response via declarative handler table
  why:  zero-allocation hot path ← static dispatch

§ DATA
  def HttpMethod't = enum[ GET, POST, PUT, DELETE, PATCH, HEAD ]

  def Request't ⟨
    method  : HttpMethod't
    path    : str
    headers : {str : str}
    body    : [u8; _]
  ⟩

  def Response't ⟨
    status  : u16 ⌈100..599⌉
    headers : {str : str}
    body    : [u8; _]
  ⟩

  def Route't ⟨
    method  : HttpMethod't
    pattern : str
    handler : &fn.handler
  ⟩

  def Router't ⟨
    routes   : [Route't; _]
    fallback : &fn.handler
  ⟩

§ OPS
  fn handle (r : &Router't, req : &Request't) → Response't
    pre:  ⌊req.path.len > 0⌋
    post: ⌈result.status ∈ 100..599⌉
    body:
      ∀ rt ∈ r.routes:
        match(rt, req) → rt.handler(req)
      → r.fallback(req)

  fn match (rt : &Route't, req : &Request't) → bool
    post: ⌈result ⇔ (rt.method = req.method ∧ pattern-matches(rt.pattern, req.path))⌉

§ INVARIANTS
  ⌈routes.count ≤ 4096⌉            # static table size bound
  ⌈handle @req < 100μs⌉             # latency budget
  t∞: ∀req: handle(r, req).status ∈ 100..599

§ TESTS
  case₁: GET "/" w/ matching-route   → route.handler invoked   ✓
  case₂: GET "/x" w/ ¬matching-route → fallback invoked        ✓
  edge:  empty path                  → precondition rejects    ✓

§ ANTI-PATTERNS
  ✗ allocate per-request ∵ GC pressure under load
  ✓ pool Response buffers ; reuse slots
  ✗ linear route scan @ 10K routes ∵ O(n) dispatch
  ✓ trie / hash-prefix match → O(1) amortized

§ RELATIONS
  handle → §logger               # feed access logs
  handle ← §config               # route table loaded at init
∎

English equivalent: ~800 words. CSLv3: ~50 lines, ~220 tokens. ≈4× compression on this spec.

§12 · Ancestry

Seven sources; each contributes one load-bearing mechanism.

Source → contribution
SourceContribution
APL / J (Iverson, 1979 Turing Award) Notation shapes cognition. One glyph per primitive op. From J: the ASCII-fallback mandate — BPE tokenizers can split single Unicode symbols into 3–5 tokens.
Ithkuil (Quijada) Slot-based morphology and the silent-defaults principle: only encode deviations from expectation.
Sanskrit Samāsa (Pāṇini, ~4th c. BCE) Five compound types that recursively compose, eliminating case particles while preserving semantic relations.
Peirce Existential Graphs (1896–1914) Spatial relations carry logical meaning. Enclosure = negation; adjacency = conjunction. CSLv3 linearizes: indent = scope, same-indent = AND.
Egyptian Determinatives Silent classifier glyphs — zero phonetic content, pure category marker. Used as domain prefixes and type suffixes.
De Bruijn Indices Positional reference eliminates naming overhead. $0, $1, $2 within three scope levels.
Lojban Unambiguous grammar — every statement has exactly one parse. CSLv3 targets LL(2).

§13 · Learning path

Suggested order for a new reader. Each step builds on the previous.

  1. Tier 0 glyphs — memorize the ~50-glyph core.
  2. Compound types — the five operators.
  3. Slot grammar — positional template + silent defaults.
  4. Morpheme stacking — aspect / modality / certainty / scope.
  5. Reasoning substrate — §P/§D/§T/§S/§C blocks.
  6. Spec template — §GOAL · §DATA · §OPS · §INVARIANTS · §TESTS · §ANTI.
  7. Worked example — read the HTTP handler end-to-end.
  8. Compiler aspects — reference compiler boundary for the executable subset.
